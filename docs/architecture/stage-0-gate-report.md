### Round-2 process-cleanup review correction

The `Start-Task16PinnedProcess` post-launch validation catch now cleans up only the exact `System.Diagnostics.Process` object returned by its own `Start-Process`: request `CloseMainWindow`, wait at most 1,000 ms, invoke `Process.Kill()` on that retained object only if needed, then wait at most 5,000 ms and recheck `HasExited`. The rethrow carries scalar `Exception.Data` fields for `Task16ProcessId`, cleanup-established/forced booleans, and validation/cleanup details. If bounded cleanup cannot establish exit, the exception message explicitly says the exact PID may still be running and must be retained/inspected. It does not kill by executable name, re-enumerated PID set, or path match.

The first implementation also put the `Process` object itself into `Exception.Data`; Windows PowerShell rejected that non-serializable value with `ArgumentException` and obscured the launch-validation error. Round 2 removes the object-valued entry; helper cleanup still runs against the exact retained object before rethrow, while callers receive the PID and cleanup result as serializable scalar fields. The installer caller preserves the PID before rethrow.
